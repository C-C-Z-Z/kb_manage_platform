### 3.2 访问鉴权与 UserContext 加载

#### 目的与场景

每个受保护接口进入前，必须先验签 Bearer JWT，校验通过后加载最新的 `UserContext`（含部门路径、角色 ID 集、操作权限码集、`permission_version`）。

#### 入口

中间件：`api/app.py:57-64` `request_id_middleware`
依赖工厂：`api/dependencies.py:111-118` `get_current_user`
权限依赖工厂：`api/dependencies.py:122-132` `require_permission`

#### 调用栈

```
api/app.py:57    request_id_middleware(request)
  └─ 为 request.state 写入/透传 X-Request-ID
  └─ call_next(request) → 命中具体路由 handler
        └─ api/dependencies.py:111   get_current_user(credentials, service)
              ├─ api/dependencies.py:101   bearer_scheme (HTTPBearer)
              └─ services/auth_service.py:70   AuthService.authenticate(token)
                    ├─ infrastructure/adapters/security_utils.py:79   JwtTokenService.parse
                    └─ infrastructure/mysql/identity_repository.py   get_user_context(user_id)
                          └─ 比对 user.permission_version 与 token.ver
              └─ 若路由有 require_permission(code) 依赖：
                    ├─ api/dependencies.py:122-132   require_permission
                    └─ 校验 code ∈ user.permission_codes
```

#### 关键步骤代码摘录

`api/dependencies.py:111-118`：

```python
async def get_current_user(
    credentials: Annotated[HTTPAuthorizationCredentials | None, Depends(bearer_scheme)],
    service: Annotated[AuthService, Depends(get_auth_service)],
) -> UserContext:
    if credentials is None or credentials.scheme.lower() != "bearer":
        raise AuthenticationError("bearer token required")
    return await service.authenticate(credentials.credentials)
```

`services/auth_service.py:70-76`：

```python
async def authenticate(self, token: str) -> UserContext:
    user_id, token_version = self._token_service.parse(token)
    user = await self._identity_repository.get_user_context(user_id)
    if not user.is_active or user.permission_version != token_version:
        raise AuthenticationError("session invalidated")
    return user
```

#### 数据流与状态变化

无写入。每次请求重新从 MySQL `iam_user` / `iam_user_role` / `iam_role_permission` 读取最新权限集。

#### 异常分支

- 缺少 Bearer 头 → `AuthenticationError("bearer token required")` → 401
- 签名错误 / 过期 → `JwtTokenService.parse` 抛 `AuthenticationError`
- `permission_version` 不一致（密码修改/退出/权限重置后发生） → `AuthenticationError("session invalidated")`，客户端必须重新登录
- 缺少操作权限 → `AuthorizationError`，403

#### 关键设计

18 个权限码在 `api/dependencies.py:155-172` 集中声明为 `Annotated` 类型别名，路由函数签名直接依赖。

### 3.3 修改密码

#### 入口

`POST /api/v1/auth/change-password`，请求体 `ChangePasswordRequest(current_password, new_password)`。

#### 调用栈

```
api/routes/auth.py:55-63    change_password(payload, user, service)
  └─ services/auth_service.py:95    AuthService.change_password
        ├─ AccountRepositoryPort.get_password_hash(user_id)
        ├─ ScryptPasswordHasher.verify(current, hash)
        ├─ ScryptPasswordHasher.hash(new)            # n=2^14, 随机 16B 盐
        ├─ AccountRepositoryPort.update_password_hash
        └─ AuditPort.record("auth.password_changed", ...)
```

#### 关键步骤

`infrastructure/adapters/security_utils.py:17-28`：

```python
def hash(self, password: str) -> str:
    if len(password) < 8:
        raise ValueError("password must contain at least 8 characters")
    salt = secrets.token_bytes(16)
    derived = hashlib.scrypt(password.encode("utf-8"), salt=salt, n=2**14, r=8, p=1, dklen=64)
    return "scrypt$16384$8$1$%s$%s" % (..., ...)
```

#### 重要细节

修改密码后**不会自动**递增 `permission_version`，存量令牌仍有效（设计如此，便于用户改完密码无需重新登录所有设备）。若需立刻下线所有令牌，调用 `POST /api/v1/auth/logout`。

```python
async def invalidate(self, knowledge_id, affected_user_ids=()):
    global_version = await self._client.incr("permission:version")
    await self._client.set(f"permission:knowledge:{knowledge_id}:version", global_version)
```

```python
    if candidate.status is FaqCandidateStatus.CANDIDATE:
        await self._repository.publish_candidate(candidate.candidate_id, (PermissionGrant(GLOBAL, "*"),), command.operator_id)
        await self._cache.invalidate_question(candidate.representative_question)
```

#### 数据流

```
qa_audit (最近 N 天) 
  → 贪心聚类 (threshold 0.85) 
    → 过滤 (≥10 次, ≥5 用户) 
      → 候选表 knowledge_faq_candidate
        ├─ signature='global' 且敏感词通过 → publish_candidate → knowledge_faq + faq_permission (global) + 失效 Redis FAQ 缓存
        └─ 其他 → status='pending_review' 等待人工
```

#### 重要阈值

`min_occurrences=10` 与 `min_users=5` 是 `FaqGapCommand` 的**固定默认值**，API 仅暴露 `window_days`。详见 `docs/后端项目总结.md` §7.1④ 与 `example/README.md` §六.1。

#### 关键实现

`workers/mysql_worker.py:62-73` `_execute`：

```python
handler = self._handlers.get(job.job_type)
if handler is None:
    await self._repository.mark_failed(job_id, "handler not found", retry=False)
    return
try:
    await handler.handle(job)
    await self._repository.mark_succeeded(job_id)
except Exception as exc:
    retry = job.attempts + 1 < job.max_attempts
    await self._repository.mark_failed(job_id, str(exc), retry)
```

`infrastructure/mysql/job_repository.py:131-149` `mark_failed`：

```python
if retry and model.attempts < model.max_attempts:
    model.status = JobStatus.PENDING
    model.run_at = datetime.now(UTC) + timedelta(seconds=2 ** model.attempts)   # 指数退避
else:
    model.status = JobStatus.FAILED
```

#### 状态机

`pending → running → succeeded` 或 `pending → running → failed → pending → running → failed ... → failed`

#### 异常分支

- handler 未注册 → 直接 `failed`（不重试）
- handler 抛异常 → 重试直到 `max_attempts=3`
- 心跳超时 → `release_stale` 把 `running` 还原为 `pending` 被重新领取

### 4.4 缓存策略

| 类型 | 键 | 失效时机 |
| --- | --- | --- |
| FAQ 应答 | `faq:answer:{问题 sha256}:{uid}:{dept}:{角色 hash12}:{perm_version}` | 发布/驳回/更新/停用 FAQ 时调 `FaqCacheInvalidationPort.invalidate_question` |
| 权限版本 | `permission:version`（全局 INCR） | 任何 `replace_grants` 操作 |
| 知识权限缓存 | `permission:knowledge:{id}:version`、`permission:knowledge:{id}:grants` | 同上 |

### 4.5 事务与并发

- 仓储层：`async with self._session_factory() as session` —— 每个方法一次会话，提交即关
- 工作流层：LangGraph 默认无事务，每个节点独立提交。**风险**：长链路（FAQ 挖掘、自动发布）的多步操作如果中间失败可能产生中间状态（详见 `docs/后端项目总结.md` §7.2⑥ 任务心跳与 §7.2⑤ 权限签名断链）
- Worker：`SELECT ... FOR UPDATE SKIP LOCKED` 保证多 Worker 不重复领取同一任务
