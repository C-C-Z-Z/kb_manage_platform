## 2. 全局约束摘要

- 认证方式：Bearer JWT，默认有效期 8 小时。
- 权限模型：操作权限 RBAC + 知识四维数据权限。
- 四维权限：global、department、role、user，按 OR 逻辑组合。
- API 前缀：`/api/v1`。
- 后端分层：API / Service / Domain / Infrastructure / Bootstrap。
- 事实存储：MySQL、Redis、MinIO、Milvus。
- 本地向量模型：BGE-M3，默认 CPU，FP16=False。
- 所有知识访问必须实时执行数据权限校验。
- 密码、Token 和模型密钥不得写入日志。
- 固定示例数据必须使用稳定 ID，并支持幂等执行。

## 3. 模块需求

### 目标
维护部门层级、用户身份、角色和菜单/按钮/接口权限。

### 页面
- /iam/users
- 部门页签
- 用户页签
- 角色权限页签

### 功能需求

#### 部门管理
- 新增、编辑、停用、删除部门。
- 维护上级部门和排序。
- 存在下级部门或成员时禁止删除。
- 部门状态变更后，影响用户的权限版本递增。

#### 用户管理
- 创建用户、分配主部门和角色。
- 启用、停用用户。
- 重置密码。
- 分配多个角色。
- 用户停用后已有令牌失效。

#### 角色管理
- 新建角色。
- 配置操作权限集合。
- 启用、停用角色。
- 删除未被用户引用的角色。
- 角色权限变化后相关用户的权限版本递增。

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | /api/v1/departments | 查询/新增部门 |
| PATCH | /api/v1/departments/{department_id} | 编辑部门 |
| POST | /api/v1/departments/{department_id}/status | 启停部门 |
| DELETE | /api/v1/departments/{department_id} | 删除空部门 |
| GET/POST | /api/v1/users | 查询/新增用户 |
| POST | /api/v1/users/{user_id}/status | 启停用户 |
| PUT | /api/v1/users/{user_id}/roles | 分配角色 |
| POST | /api/v1/users/{user_id}/password-reset | 重置密码 |
| GET/POST | /api/v1/roles | 查询/新增角色 |
| GET | /api/v1/roles/permissions | 权限定义 |
| POST | /api/v1/roles/{role_id}/status | 启停角色 |
| PUT | /api/v1/roles/{role_id}/permissions | 配置角色权限 |
| DELETE | /api/v1/roles/{role_id} | 删除未被引用角色 |

### 验收标准
- 用户、角色、部门数据中文显示正常。
- 角色调整后旧会话失效。
- 部门被下级或用户引用时删除失败。
- 停用用户立即无法登录。

### 当前实现对照
部门、用户、角色页面和 API 已实现。部门列表当前为表格展示，尚无拖拽树；用户筛选和最近登录时间可作为下一阶段增强项。
