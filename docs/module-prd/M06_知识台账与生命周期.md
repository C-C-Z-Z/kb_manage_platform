## 2. 全局约束摘要

- 认证方式：Bearer JWT，默认有效期 8 小时。
- 权限模型：操作权限 RBAC + 知识四维数据权限。
- 四维权限：global、department、role、user，按 OR 逻辑组合。
- API 前缀：`/api/v1`。
- 后端分层：API / Service / Domain / Infrastructure / Bootstrap。
- 事实存储：MySQL、Redis、MinIO、Milvus。
- 本地向量模型：BGE-M3，默认 CPU，FP16=False。
- 所有知识访问必须实时执行数据权限校验。
- 密码、Token 和模型密钥不得写入日志。
- 固定示例数据必须使用稳定 ID，并支持幂等执行。

## 3. 模块需求

### 目标
统一管理知识资产，支持筛选、创建、编辑、发布、停用、归档和批量操作。

### 页面
- /knowledge

### 功能需求

| 编号 | 需求 |
| --- | --- |
| KB-F01 | 按标题、知识 ID、分类和状态筛选 |
| KB-F02 | 新建知识草稿 |
| KB-F03 | 编辑标题、分类和标签 |
| KB-F04 | 发布知识 |
| KB-F05 | 停用知识 |
| KB-F06 | 归档知识 |
| KB-F07 | 批量发布、停用和删除 |
| KB-F08 | 只有已发布且当前版本已索引的知识进入普通检索 |
| KB-F09 | 知识管理员的阅读能力仍受数据权限控制 |

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/knowledge | 分页列表 |
| POST | /api/v1/knowledge | 新建草稿 |
| GET | /api/v1/knowledge/{knowledge_id} | 知识详情 |
| PATCH | /api/v1/knowledge/{knowledge_id} | 更新元数据 |
| POST | /api/v1/knowledge/{knowledge_id}/publish | 发布 |
| POST | /api/v1/knowledge/{knowledge_id}/disable | 停用 |
| POST | /api/v1/knowledge/{knowledge_id}/archive | 归档 |
| DELETE | /api/v1/knowledge/{knowledge_id} | 物理删除 |

### 数据表
- knowledge_unit
- knowledge_permission
- knowledge_version

### 状态流转
- draft -> published
- published -> disabled
- disabled -> published
- published/disabled -> archived
- 任意可访问状态 -> deleted

### 验收标准
- 新建知识默认 draft。
- 未配置权限的知识默认不可被其他用户访问。
- 停用或归档后不进入 AI 检索。
- 批量操作对部分失败应有明确反馈。

## 4. 依赖与交付说明

- 本模块的接口均以 `/api/v1` 为统一前缀。
- 权限码、资源状态和接口字段发生变化时，必须同步更新总体 PRD、迁移和前端权限。
- 模块验收应同时覆盖成功路径、权限拒绝、参数错误和依赖异常。
- 示例数据或初始化模块发生变化时，必须保持固定 ID 和幂等性。
