## 2. 全局约束摘要

- 认证方式：Bearer JWT，默认有效期 8 小时。
- 权限模型：操作权限 RBAC + 知识四维数据权限。
- 四维权限：global、department、role、user，按 OR 逻辑组合。
- API 前缀：`/api/v1`。
- 后端分层：API / Service / Domain / Infrastructure / Bootstrap。
- 事实存储：MySQL、Redis、MinIO、Milvus。
- 本地向量模型：BGE-M3，默认 CPU，FP16=False。
- 所有知识访问必须实时执行数据权限校验。
- 密码、Token 和模型密钥不得写入日志。
- 固定示例数据必须使用稳定 ID，并支持幂等执行。

## 3. 模块需求

### 目标
识别无候选、低置信度和权限受限问题，将真正知识缺口转化为补充草稿，并在知识发布后闭环。

### 页面
- /operations 的知识缺口页签

### 功能需求
- 按时间窗口检测缺口。
- 缺口包含代表问题、类型、频次、部门、最大相似度和建议分类。
- 支持手动忽略并填写原因。
- 支持一键转建知识补充草稿。
- 一个缺口可关联多个草稿。
- 全部相关草稿发布后自动标记已解决。
- 权限受限不能误判为无知识。

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/v1/gaps/detect | 检测缺口 |
| GET | /api/v1/gaps | 缺口列表 |
| POST | /api/v1/gaps/{gap_id}/convert | 转建草稿 |
| POST | /api/v1/gaps/{gap_id}/status | 解决或忽略 |

### 状态流转
```
pending -> converted -> resolved
        \-> ignored
```

### 验收标准
- 权限受限问题不会进入无知识缺口。
- 转建后可在知识台账看到 draft。
- 知识发布后关联缺口变为 resolved。
