### 关键架构事实（后续复用）

- 六边形分层：`api → services → engines → domain`，`infrastructure` 实现 `domain/ports.py` 的 36 个 Protocol，`bootstrap/container.py` 为唯一手工组合根（333 行）
- 4 条 LangGraph 工作流：`query_engine`(10 节点,含两路并行检索+双重鉴权) / `ingestion_engine`(8 节点串行) / `knowledge_engine`(9 节点,按 KnowledgeAction 路由) / `faq_gap_engine`(8 节点,二次条件路由)
- 异步方案刻意不用 Celery/RabbitMQ：MySQL `background_job` 表 + `SKIP LOCKED` + 心跳 + 指数退避 + 调度器时间片幂等键
- 权限两层：RBAC 18 个权限码（`api/dependencies.py` 硬编码）+ 四维数据权限（`PermissionPolicy`，global/department/role/user OR 判定，默认拒绝）

### 已定位的代码问题（供后续修复参考）

**高优先级**
1. `node_auth_filter` 只在异常时写 warning，**回答中缺「部分参考资料因权限受限无法展示」提示**（PRD 2.9.4 / 验收标准 5 未达标）
2. `knowledge_service.list_units` 硬编码 `limit=1000` 后在内存过滤分页 → **第 1001 条起数据永久不可见**（数据正确性 bug）
3. `/query/stream` 先 `await` 完整回答再发单个 delta → 伪流式
4. `model_config` 表仅由 `ConfigurationService` 读写，`build_container()` 实际仍从 `Settings(.env)` 构造适配器 → 配置中心运行期不生效

6. `MYSQL_JOB_LOCK_TIMEOUT_SECONDS=300` < `MINERU_TIMEOUT_SECONDS=600`，且执行期无心跳 → 多副本/重启时任务被误回收重复执行

8. 聚类用 `difflib.SequenceMatcher` 字符相似度，非语义，中文场景达不到 PRD「语义去重」要求
9. Token 用 `len(text)/2` 估算，未取 LLM `usage`
10. 上传仅校验后缀，无体积/数量上限（`mineru_max_file_mb` 在解析阶段才生效）

### 验证结论（已实测，验证数据已清理）

- 内置账号仅 3 个（admin / kbadmin / demo），**无法手动满足 FAQ 挖掘的 `min_users=5` 阈值**，必须在 README 提供 SQL 造日志方案
- FAQ 挖掘阈值 `min_occurrences=10` / `min_users=5` 是 `FaqGapCommand` 固定默认值，**接口只暴露 `window_days`，不可调**
- **全局签名 FAQ 会自动发布**：`NodeMineFaq` 对 `status == CANDIDATE`（即 `permission_signature == "global"` 且通过敏感词检查）的候选直接调 `publish_candidate` 授予全局权限并清缓存；实测挖掘后候选状态直接是 `published`
- FAQ 缓存键 = `faq:answer:{问题sha256}:{user_id}:{department_id}:{角色hash12}:{permission_version}`，按用户维度隔离；匹配走 `question_hash()` 规范化**精确匹配**，同义不同问法不命中
- 场景一演示账号选择：`02-高管薪酬` 权限设为「部门=人力资源部 + 角色=知识管理员」，则 `demo`(role-user) 被拦截、`kbadmin`(role-knowledge-admin) 放行，无需新建账号
- 环境已运行：mysql/redis/minio/milvus/etcd/attu/backend/worker 共 8 容器；`SEED_DEMO_DATA=true`
- 数据库凭据来源：`backend/.env`（含 `MYSQL_ROOT_PASSWORD`），项目根**无** `.env`
